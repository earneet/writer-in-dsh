# 参照小说学习流程（reverse-reference）

## 定位

参照学习是**一次性的提炼动作**，不是持续模式：读参照文本 → 提炼技法 → 沉淀到 `style/` 实体 → 之后在创作中引用。不建分析表、不做逐段自检（原项目 reverse_analyses 表与 selfcheck 循环已裁定抛弃，见 docs/novel-writer-review.md §抛弃②）。

## 流程

1. **收文本**：用户给出参照片段（一章、一节均可；太短提不出结构结论时先说明局限）。
2. **提炼**（一次完成，围绕四问）：
   - **视角与叙事**：第几人称、视角距离（贴身/全知）、时态习惯、信息释放顺序（悬念怎么摆）。
   - **节奏**：场景切换粒度、对话/叙述/描写占比、章节钩子（开头结尾怎么收放）。
   - **对话风格**：提示词密度（「他说」类）、口语化程度、潜台词处理。
   - **描写密度**：环境/心理/动作描写的比例与触发时机（何时慢下来）。
3. **沉淀到 style 实体**：`writer_update(entity="style", id="<ASCII 技法名，如 kinetic-dialogue>", expectHash="new")`（id 仅允许字母/数字/下划线/连字符，中文名会被拒——中文语义放正文），一条正文写清「技法 → 参照中的证据（短引文）→ 怎么用到本项目」。多个维度可以分多条 style 实体，也可以合成一条。
4. **回链**：如果提炼结果影响全篇基调，建议用户把它并入 `principles`（准则仍是最高约束）；style 是素材库，principles 是法律。

## 纪律

- **引文仅短摘录**：每条技法配 1-2 句参照原文作证据即可，不整段复制参照作品（版权红线）。
- **学结构不学内容**：提炼的是技法与结构，不是情节、人设、专有名词——不得把参照作品的故事元素带进本项目正文。
- **read-before-update**：改已有 style 实体先 `writer_read` 取完整 hash。
- 参照文本本身**不落盘**到项目实体（避免版权材料入库）；只沉淀提炼结论。

## 与写作的衔接

写作前 `writer_read(entity="style")` 盘点可用技法；想让本章用某种风格时，把要点写进 `write_chapter` 的 `instruction`（如「对话风格参照 style/kinetic-dialogue：短句、少提示词」）。
