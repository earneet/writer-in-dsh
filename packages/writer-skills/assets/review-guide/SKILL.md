# 审稿指南（review-guide）

## 3+1 维度定义

`review_chapter` 输出四维结构化建议（可用 `focus` 参数只审其中几维，逗号分隔）：

| 维度 | 检查什么 |
|---|---|
| 情节一致性 | 与大纲、前文章节、伏笔档案是否矛盾；因果是否成立 |
| 人物一致性 | 行为是否符合人设与当前状态时间线（chapter frontmatter `timeline` 为准）；语气是否漂移 |
| 设定一致性 | 与世界观条目、创作准则中的规则是否冲突 |
| 文学质量 | 文笔、节奏、对话自然度、描写密度（唯一的主观维） |

- 建议字段：`[severity] 维度：问题` + 原文 `quote` 定位 + `建议` + 可选 `改写方案`。
- **quote 是从正文逐字摘录的定位锚**：引擎会校验 quote 是否真实存在于正文，与正文不符的建议会被丢弃——所以引用原文时必须逐字复制，不要凭记忆转述。
- 没有问题的维度不会出现建议；「无结构化建议」就是干净通过，不要编造问题。

## severity 分级与处理

- **high**：一致性硬伤（矛盾、ooc、设定冲突）——必须处理：`write_chapter(mode="rewrite", instruction=按建议改)` 后复审。
- **medium**：可疑但不确定——向用户报告并给判断，由用户裁定是否改。
- **low / 文学质量类**：润色建议——批量汇总给用户，不建议逐条自动改稿（避免风格漂移）。

## 工作流（审 → 报 → 改 → 复审）

```
review_chapter(chapter, focus?)
  → 有 high：write_chapter(rewrite, instruction 逐条引用建议)
  → rewrite 后对改过的维度复审一次（focus 收窄）
  → 维护类更新（伏笔/时间线/事件）在审稿收敛后进行（见 chapter-writing「审稿先行」）
```

- 审稿报告是**预览不落盘**：处理完的建议不需要存档，落实手段就是改稿或维护实体。
- 一次只审一章；全书级矛盾用 `consistency_check`（不同工具，输出全书矛盾报告）。

## 报告给用户的格式

按 severity 从高到低转述，每条给：维度、问题一句话、原文引文（截断到关键句）、建议。high 条目明确说出「建议改稿」，并询问用户是否立即执行 rewrite。
