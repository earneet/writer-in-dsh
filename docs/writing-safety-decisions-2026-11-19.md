## 决策与验收

- [x] **选区改稿。** 明确提供的选区必须在当前章唯一定位。补丁只在原选区内应用，整组校验后再按章稿哈希保存。模型返回全文、区外补丁或无法可靠定位时保留原稿，由作者重新选定范围或明确发起整章改稿。验收检查区外逐字不变、失败不保存、不触发章后维护，原有无选区的整章改稿仍可用。
- [x] **待确认建议。** 新投递节携带源章稿哈希，沿用 Markdown 活跃清单及只增归档。工作台识别当前、已作废、源章变化和版本待核。旧条目原文可查。准备确认请求时携带源章版本并要求在写权威记录前复读核对。验收覆盖同章新旧建议、显式标记同一版本、旧格式和工作台按原样展示归档。
- [x] **单章审稿。** 沿用当前单次、按维度审稿及只读回执。按维度送入有界的历史正文、已确认事件、人物时间线及世界观规则。硬冲突需有本章原句和可回查的参考来源。回执披露材料缺少或裁剪。验收使用测试模型捕获实际请求，验证未来事实过滤、证据引用及材料不足回执。
- [x] **Windows 冒烟。** 复用现有浏览器夹具，建立可从干净 Windows checkout 重跑的一条命令并接入 CI。本机 Edge 已完成首轮前建书、改稿草稿交接、旧格式归档入口和源章改动后的待办刷新。

## 有意保留的差异

### 1. 选区改稿采用整组校验

上游 `write-chapter-tool.ts` 的选区流程以选区作为局部原文，部分补丁命中时可继续，全部失配时可回退到模型直接生成局部文本，拼接时使用原文中第一个匹配位置。本项目只允许 `rewrite` 携带选区，要求选区及每个原始锚点唯一，锚点互不重叠，整组通过才保存。失配会返回原因和重新选区的提示。无选区的整章改稿仍沿用既有路径。

本项目使用 Markdown 存储层读出的正文作为比较基线。存储规范化若会影响选区外正文，拒绝保存。这样能将作者给出的范围作为写入边界，并避免把未经验证的模型全文展示成可采纳改稿。若日后增加可预览的直接选区替换，应先定义明确的选区位置、版本和确认机制，并继续保证区外正文逐字不变。

### 2. 待办按 Markdown 记录来源和确认依据

上游 `pending-fact.ts` 为逐条事实保留数据库状态，并在确认时分发到目标服务。本项目在 `pending.md` 的维护节记录章稿哈希，以现有 `pending-archive.md` 保留历史。工作台区分当前稿件、已作废、源章变化与版本待核。准备的确认要求会提示助手重新检查待办节、读取源章完整哈希并向作者确认，再调用现有权威实体工具。

工作台检查和工具重新读取是两次核对，源章与目标实体的跨文件写入仍使用各自既有的并发语义。旧条目缺少来源哈希时由作者重新核对或重算。带有明确三位章号的旧人工节仍支持整章归档。只有需要持久化逐条处置或跨文件事务时，才重新评估这个安排。

### 3. 单章审稿使用一轮、有依据的只读报告

上游 Agent 工具提供评分和解析重试，并与 autopilot 审修复用。上游独立审稿服务还能按维度调用并持久化报告。本项目使用宿主的一次模型调用，保留四维结构化建议和整章正文，旁证共享 `contextBudgetChars`，覆盖回执列明缺失及裁剪。涉及历史的材料按章过滤，人物时间线取目标章及以前的有效条目。结构化硬冲突需要本章原句和对应维度、实际送审的来源引文；缺证据的条目降为待核对。引文验证证明引用确实存在，冲突是否成立由作者判断。

这种安排适合短反馈循环，也避免把评分、自动改稿或报告持久化变成日常审稿的前置步骤。既有自由文本设定依赖作者使用章锚表达时间可见性。只有真实语料评测证明当前分组优先级或单次审稿漏检显著时，再评估检索排序、按维度多次审稿或报告持久化。

### 4. 浏览器冒烟与桌面验收各自取证

发布流程按本项目的 dsh 宿主交付形态制定。Windows CI 使用锁定宿主前端的浏览器夹具检查真实磁盘和输入草稿交接。Electron 预发验收使用隔离 profile，另行检查包安装、真实会话、模型和真人审批。升级宿主时沿用此验证边界，分别保留日志和实际产物。
