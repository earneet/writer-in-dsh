## 执行计划与确认边界

1. 核对领域功能、现有界面和宿主接口 → 验证：每个页面与动作能对应现有数据或明确列出的依赖。
2. 制定并自行复审信息架构与视觉方向 → 验证：覆盖写前、读稿、改稿、确认维护三条高频路径，遵守既有边界。
3. 制作关键页面可交互设计稿 → 验证：导航、选章、查看人物、伏笔筛选与待确认详情可操作；示例内容明确标识。
4. 独立对抗审查并逐条复核 → 验证：无虚构能力、无未交代的数据来源、无不可完成的主要操作。
5. 向用户展示具体方案并确认 → 验证：用户批准本文件及其对应设计稿后，进入产品实现。
6. 确认后实施并验证 → 验证：`npm run typecheck`、`npm test`，浏览器亮暗主题、不同宽度和键盘路径通过；审查循环收敛；追加实施计划 §8。

当前阶段：用户已确认百章目录修订版并授权实现，步骤 1～6 已完成。产品实现与最终验证见 `docs/ui-implementation-2026-11-17.md`；下文设计阶段的预览与审查记录保留原上下文。

## 设计方向与方案比较

| 方案 | 价值 | 代价与适用性 |
|---|---|---|
| 八页签视觉翻新 | 最小改动，熟悉旧版的用户容易适应 | 正文与资料仍困在折叠列表，任务之间切换频繁；不足以达成“好用”目标 |
| 数据总览驱动 | 全书进度、问题数量一览清楚 | 日常阅读与改稿多一层跳转，容易把低频统计放在高频工作之前 |
| 章节为中心的写作工作台（推荐） | 目录、正文、关联资料同处一个语境；人物/伏笔/待确认有独立深度视图 | 需要拆分现有大面板，补齐明确的导航状态与宿主操作桥接 |

用户已确认“章节为中心的写作工作台”，包括按需百章目录修订。视觉方向：克制的书稿排版、低对比结构线、正文留白与少量强调色；深浅外观均与宿主协调。

## 1. 目标与非目标

目标是让作者能连续完成“找到这一章 → 阅读与核对 → 提出续写或修改要求 → 查看 Agent 回执 → 确认章后建议”。打开项目后先看到稿件及可继续的工作，而不是先读一屏统计。人物、伏笔、设定需要可定位、可联动、可完整阅读。

本次保留 React、动态客户端插件、会话视图入口和现有 Markdown 数据总线；重设计 `writer-ui`，不重建会话、Agent Loop、工具调度、权限、模型配置或独立数据库。不把上游的节拍确认、版本管理、拖拽排序、自动灵感消化或章节审批状态机作为本版已有功能。

设计稿使用《长夜有歌》的项目设定作为内容语境，章节片段、数量和待确认条目为设计示例，不能当作仓库当前小说的实际状态。预览中的业务动作仅展示请求内容，不连接模型或修改文件。

## 2. 现状与必须保留的能力

当前 `Panel.tsx` 是八个等权页签：概况、大纲、章节、伏笔、人物、灵感、设定、待办。章节全文被放在折叠行内，正文使用 12px 字号并限制局部高度；待办最多显示六节、每节十五行，超出部分只提示数量，没有继续展开入口。新设计需要解决这些阅读与访问问题。

保留 `types.ts`、`graph.ts`、`project.ts` 的实体与索引、`bus.ts` 数据总线、`load.ts` 冷启动扫描及增量订阅、`Cards.tsx` 的十四工具结果覆盖。工具卡片仍在宿主对话流里，使用宿主信封与运行状态；领域工作台使用适合长文阅读的布局。

所有计数来自实际扫描或工具结果；未设置目标时不显示百分比。统计明确标为“字符数”或“约字数”，不新增没有数据源的日更、连续写作天数、质量评分。章节状态保留源 frontmatter 原值，可做显示翻译，但不能暗示本仓有审核或定稿工作流。

## 3. 信息架构

保留宿主“对话 / 轨迹 / 写作面板”的入口关系；插件内部显示“写作工作台”标题。页面可用宽度按插件容器计算，不按整个显示器计算。

```text
宿主会话导航：对话 | 轨迹 | 写作面板
┌ 项目：《长夜有歌》 · 当前页面              文件同步状态 · 刷新 ┐
│ 创作导航       │ 页面主体                     │ 按需关联信息  │
│ 稿件           │ 章节目录入口 / 上一章·下一章   │ 本章大纲      │
│ 大纲           │ 或大纲 / 人物 / 伏笔等深度页   │ 关联伏笔      │
│ 人物           │                               │ 创作准则      │
│ 伏笔           │                               │               │
│ 资料           │                               │               │
│ 待确认 · N     │                               │               │
│ ─────────     │                               │               │
│ 全书概况       │                               │               │
└───────────────────────────────────────────────────────────────┘
```

一级导航为七项；“资料”收纳世界观、创作准则、重要事件、风格示范和灵感原文。“待确认”是 `pending.md` 的友好名称，内部仍沿用现有待办和归档语义。全书概况为低频独立页面，位置靠后，保留进度、卷分布、风险摘要和本会话动态。

默认进入稿件；首次无章节时进入有明确下一步的稿件空态，提供“大纲”和“准备第一章请求”。不根据“最大章号”声称用户上次正在编辑的章节；首次选择最近章节，之后记住当前会话内用户实际选章。切页面、查看关联人物后返回，保留选章、列表筛选和阅读位置；切换会话按 sessionId 隔离并清空旧项目可见数据，扫描失败也不得把旧会话内容展示给新会话。

## 4. 核心页面与交互

### 4.1 稿件：目录、书稿、关联资料

百章容量修订后，左侧只保留七个功能入口，移除其下常驻的章节列表。正文顶部常驻“章节目录 · 当前章 / 总章数”，正文底部保留上一章/下一章；章数增加不增加左栏或正文页面高度。选择章节属于稿件页内的局部导航，不与全局功能导航竞争同一列。

点击“章节目录”打开独立选择浮层：搜索框支持全书标题与精确章号直达，输入 `128` 可直接定位第 128 章；按卷选择浏览范围，当前卷默认展开为局部列表。列表每页最多八条，固定预留八行高度，上一页/下一页切换，不把一百多行全部挂到页面。搜索匹配也分页；空结果给明确说明，清空搜索恢复卷内范围。打开时自动选中当前章所在卷和所在页，“定位当前章”可恢复这一位置。选章后关闭浮层并更新正文、关联信息与动作上下文；Esc 关闭并返回目录按钮。窄屏仍使用同一选择逻辑，不把全部章节平铺在导航下。

没有分卷的作品按每 25 章生成临时浏览分组；超长单卷也可分组或继续分页，分组只影响 UI，不修改 Markdown 的卷归属。原始章号允许有缺号，上一章/下一章遍历实际存在的章节，不能用章号加减假定下一文件存在。输入不存在章号时显示未找到；计划但未写的章由大纲入口处理，不伪装成已有正文。

此方案替代“在功能导航下加独立长滚动区”：后者虽能固定比例，作者仍需在百行目录里反复拖动。按需目录 + 分卷/分组 + 直达查找更适合本次阅读工作台；需要长时间编排结构时使用大纲页。预览以六卷、150 个虚拟章项验证容量；前三章有原示例片段，其余为目录与正文占位样例，不代表真实项目已写到该章。

正文是主要视觉区域：章号、标题、约字数、来源状态在上，全文连续阅读。正文区只有一个纵向阅读滚动面，不再为每个小节加滚动框。主要操作为“续写本章”，次要操作为“审阅本章”和“提出修改”；正文阅读页明确标识“阅读”，不出现无法保存的编辑框或自动保存提示。

“提出修改”打开请求编辑区，默认带当前章 id；允许作者填写原文引用、修改意图与约束。没有可靠选区协议时不把任意拖选包装成精确补丁定位。提交前显示“将交给助手的要求”；准备稿件动作由宿主对话执行，`write_chapter` 成功回执后才认为保存完成。

关联侧栏为“本章大纲 / 关联伏笔 / 创作准则”。章节与大纲、伏笔的关联用现有章号索引；人物不能在缺少可靠标注时被推断为“本章出场”，入口应标为“查阅人物”。全文人物资料在人物页；侧栏只显示有来源的摘要和跳转。

### 4.2 大纲：计划和稿件对照

以卷、幕、章结构树为左侧选择器，右侧显示所选小节全文。章叶显示“已有正文”或“未写”，可跳稿件；未锚定章节单列并说明原因。保留原始 Markdown 大纲，界面不提供不可落盘的拖拽排序。编辑大纲准备对话请求，已写章的情节调整提示考虑一致性检查。

### 4.3 人物：可检索名册与人物档案

人物列表配姓名、角色和简短身份；选中后显示完整档案，顶部固定提供“档案 / 关系 / 状态时间线”三个内部视图。以正文与时间线为默认信息面，人物首字标识只是导航辅助，不用大量重复的头像圆卡填满页面。

时间线按章顺序排列，章号可跳稿件。缺失章节仍保留原锚并显示“暂无正文”。关系以所选人物为中心显示，明确“该人物声明的关系”和“他人指向该人物的关系”；无法匹配的名字保留文本提示。人数较多时优先使用邻接列表，关系网络作为辅助视图，避免大环形图成为默认入口。

### 4.4 伏笔：按创作动作组织

提供“全部 / 本章待埋 / 本章待收 / 已逾期 / 已收束”筛选，列表行显示伏笔标题、当前状态、目标章与提示，选中查看描述和完整生命周期。状态和章锚使用中文标签与文本，颜色为辅助。

必须校准两套章锚：`planned_chapter` 表示计划埋设；`resolve_chapter` 表示计划回收。planned 状态只计算埋设任务，planted 状态只计算回收任务；缺少相应锚时显示“未设计划”，不编造逾期天数或章节数。以用户选定章为“本章”范围，以全书当前章计算全书逾期，两者明确区分。

“讨论如何回收 / 准备状态更新请求”交给宿主 Agent，不能在本地点击后直接显示已回收。只有工具成功并读到新的 Markdown 后更新状态。强化、半揭示、回调、红鲱鱼作为生命周期事件，不冒充状态机的新状态。

### 4.5 待确认：读懂建议后再操作

按章节列出 `pending.md` 的原始建议，显示待办行数和来源节标题；重复建议沿用现有归一化语义。左侧章节/维护节列表，右侧完整建议与上下文。默认先显示最新一节，通过“显示更多”访问全部节和全部行；历史归档同样可以展开到完整内容。

待确认条目使用“建议”图标和文本，不再画不能勾选的复选框。现有数据是 Markdown 文本行，不能可靠解析时按原文显示；不得伪造人物/伏笔类别、置信度或逐条持久化的接受状态。

“让助手处理本条”只准备携带原文与章号的请求；确认人物状态用 `timeline_update`，伏笔变更用 `foreshadow_update`，其余根据实体更新。整章的“归档本章建议”说明归档范围：`pending_cleanup(chapter)` 会归档该章的待办节，不能伪装成逐条忽略。动作成功前维持原列表，成功后以文件扫描为准。

### 4.6 资料与全书概况

资料库将创作准则、世界观、重要事件、风格示范、灵感原文分组；左列表右全文。灵感醒目标注“原文”，整理请求不覆盖作者原话；不添加虚构的自动消化状态。搜索只在已经加载的资料标题/文本内筛选；语义检索独立标为“让助手检索”，使用现有 `writer_search`，结果披露降级状态与章范围。

全书概况展示真实字符进度、章节/人物/伏笔/待确认数量、风险和维护摘要。最突出的入口为“阅读最近章节”，其次为“查看待确认建议”。导出入口归这里，填写格式与范围后准备 `export_book` 请求，审批由宿主呈现；不新增本地批准按钮。

概况的低频“项目操作”收纳“创建存档点”（`archive_point`）、“更新章节摘要与关联信息”（`recompute_derived`）、“等待章后整理完成”（`maintenance_flush`）。存档仍是明确 Git 操作，不展示不存在的版本还原面板；整理入口解释面向作者的结果，工具名称仅在详情里供追溯。

| 既有领域能力 | 新版入口 | 结果依据 |
|---|---|---|
| `writer_read` / `writer_update` | 资料阅读、提出修改请求 | Markdown 扫描与读写回执 |
| `write_chapter` | 稿件续写、修改；未写章准备写作 | 工具保存回执与新正文 |
| `review_chapter` / `consistency_check` | 本章审阅、全书检查 | 原文引用、建议与覆盖披露 |
| `foreshadow_update` / `timeline_update` | 伏笔任务、人物时间线、待确认处理请求 | 更新后的权威实体 |
| `pending_cleanup` | 待确认中的归档本章建议 | 该章待办移出与完整归档原文 |
| `writer_search` | 资料查证请求 | 检索结果、章范围及降级披露 |
| `writer_stats` / `archive_point` | 全书概况与项目操作 | 真实统计、限定小说范围的存档回执 |
| `recompute_derived` / `maintenance_flush` | 章后整理、改稿后的资料更新 | 派生新鲜度与工具结果 |
| `export_book` | 全书概况中的导出入口 | 宿主审批后的导出路径与告警 |

## 5. 视觉系统

视觉意象为“安静的书稿与有条理的书桌”。避免大面积品牌色、渐变、重复卡片、整屏状态徽章和仪表盘式数字堆积。

| 项目 | 规格 |
|---|---|
| 色彩 | 以宿主当前背景、文字、边框、状态 token 为基准映射 `--writer-*`；品牌色仅用于当前选择与主要动作。设计稿的低饱和绿为方向示意，落地优先映射宿主品牌变量 |
| 层级 | 导航弱背景，主体正常背景，正文由排版和留白形成中心；少量结构线，不给每段内容加卡片边框 |
| 字体方案 | 首选：宿主中文 UI 字体 + 本地宋体类书稿字体；备选：全部沿宿主字体。章节标题 24～28px，正文 17～19px，UI 13～14px，辅助信息 12px；不依赖在线字体加载 |
| 阅读节奏 | 正文行高约 1.9～2.0，段间距约 0.8em，最大行宽约 34～40 个汉字；窄屏自然缩小行宽而不缩字号 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px 六级；页面主体留白 24～40px；紧凑列表行高至少 36px |
| 圆角 | 按钮约 6px，选择行约 6～8px，浮层约 10px；遵循宿主基元可配置范围，不强制覆盖其内部样式 |
| 状态 | 同时显示文字与语义色；正常同步保持低强调，错误有文字、范围和重试入口，不持续显示红色大横幅 |
| 动效 | 页/面板切换 120～160ms，小幅透明度变化；无持续装饰动画；尊重 reduced-motion |
| 焦点 | 保留宿主清晰 focus ring；图标动作有中文可访问名称；主要动作始终有可见文本 |

## 6. 适配与界面状态

以工作台容器宽度判断：≥1100px 显示约 175～200px 功能导航、弹性正文和约 240px 关联栏；820～1099px 保留功能导航和正文，关联资料由按钮展开；更窄时功能导航压缩为菜单或换行，章节目录始终由正文顶部按需打开。目录选择浮层保持有界行数，随宽度缩小而缩窄，不因章数变长；目录按钮、上一章/下一章在亮暗主题及窄容器下均可达。关联信息可关闭，正文总是保留优先空间。

加载时展示结构化骨架；刷新时保留同项目旧数据，显示“正在刷新”，不整页闪空。首次无项目与无章节分别给出可执行入口。读取部分失败列明文件和影响，已读内容继续可用；监听不可用显示“手动刷新”并提供按钮，不声称实时同步。成功收到目录流不等于子目录每个文件都可实时监测，不能用一个绿色点替代真实覆盖说明。

工具运行时由宿主对话展示运行与取消；工作台如能取到本会话活动则显示简短关联信息，不能根据一个旧回执猜测当前进度。错误、拒绝审批、取消均保留现有正文，允许重新准备请求；不做成功态的乐观伪装。

## 7. 产品实现边界

实现优先改客户端，不新增服务端 remote，也不改 reference 子模块。已经按实际安装的 `0.2.2-rc.1` 核验以下接线：

1. `index.tsx` 的槽包装保留 `sessionId`、`openView`、`inputActions`、`useInput`，补声明 `conversation` 服务依赖；所有动作绑定来源会话。
2. `ctx.sessions.binding(sessionId)` 取得仍被保留的会话实例；不存在或已过代时不追加到其他会话。
3. `ctx.conversation.input.requestDraftInitialization(binding, { prompt, whenDraftExists: 'append' })` 追加新段。该接口保留已有文字、引用和附件；禁止以 `setDraft(existing + request)` 替代，因为后者会移除引用。
4. 仅返回 `applied` 时调用 `inputActions.persistDraft()` 后 `openView('chat', '')`；`preserved` 保留预览并说明未追加，`blocked` 保留预览并允许稍后重试或复制。命令式草稿先提示并保留原文，避免把自然语言拼为命令参数。整个过程不调用 submit/send，不自动排队或 steer。
5. Agent 生成中不等于草稿锁定；由宿主输入状态判定是否能追加。备稿成功只显示“已添加到对话草稿”，不能显示工具成功或内容已保存。

依据为安装包 `node_modules/@deepseek-ai/dsh-api-session-controller/lib/types/client/sessions/service.d.ts:248`、`dsh-client-ui-conversation/lib/types/client/contract/input.d.ts:205`、同包 `contract/slots.d.ts:481` / `:532`。正式实现仍须用真实会话验证注入和槽 props，不以文档阅读替代集成验收。宿主能力不可用时保留请求预览与复制途径。

页面可操作状态、已选择实体、筛选与阅读位置是派生 UI 状态；按 sessionId 区分，不能变成内容的第二权威来源。作品正文、人物状态与伏笔状态仍以 Markdown 为准。工具结果和文档之间联动保留原 sessionId，不能依赖“当前全局活跃会话”的猜测。

这要求调整数据总线，而非仅加页面 state：目前 `bus.ts` 的扫描快照为模块级单份、工具动态按 activeSessionId 分桶；改为显式 sessionId 的读写/订阅/去重键，异步扫描用会话与代次双重校验。工具槽在安装宿主中属于 session scope，应把所属 sessionId 传入记录路径。只修正文布局而保留旧全局扫描快照，不能通过本次隔离验收。

实体补齐范围明确为：伏笔实体保留 `resolve_chapter` 和完整正文（现只有预览），风险投影分别消费埋设/回收章锚；动作请求携带具体实体 kind、id、章号及用户看到的建议原文。关联链接传稳定定位对象，不以“当前选中的伏笔”之类全局隐式指代替代上下文。

## 9. 自审检查

- 是否直接服务写作：默认正文，统计降位；读稿、查资料、准备修改要求有连续路径。
- 是否增加范围：保持插件客户端形态；不增编辑器、数据库、Agent Loop、独立审批和上游未复刻的状态机。
- 是否有更简单替代：单纯换色无法解决正文受困与待办截断，因此保留工作台布局；关系图和复杂时间线画布降为辅助，不作为首轮重心。
- 是否有副作用：导航迁移可能丢旧入口；逐项核对八旧页签和十四工具卡片覆盖。会话切换、数据读取失败和宿主草稿是重点回归面。
- 是否虚构业务能力：区分草稿、发送、保存、归档四种动作；设计稿演示不连接业务，不能据此宣称实际插件已完成。
