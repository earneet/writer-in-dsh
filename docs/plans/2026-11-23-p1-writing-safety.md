## R1 · 导出文件与原稿隔离

**拟定行为**

- 默认输出到作品内 `exports/`，保留部署者配置项目内独立导出目录的能力。工具参数 `output_path` 仍以作品根为基准，只能选在该导出目录内，扩展名须与格式一致。导出服务拒绝与已知权威文档、目录及缓存路径重叠的目录配置，按 Windows 实际路径语义比较大小写，检查真实父目录位置并拒绝路径上的符号链接、目录联接及其他已知重定向。先完成路径检查，再创建目录、生成和发布。
- 默认采用可预测的编号文件名，如 `book-2.epub`。即使批准导出，已有同名产物仍保留。新产物在目标同目录完整写好后，以目标已存在即失败的方式发布。并发争用同名时试用下一个候选。占用、写入或发布失败则给出可操作提示，清理本次临时文件。回执返回实际产物路径。
- 保留宿主真人审批。审批展示格式及所请求的目录或文件名，说明同名时自动编号。拒绝审批时不会进入导出服务。选择独立导出目录是比维护一份作品文件黑名单更稳定的隔离方式。将来如有替换旧导出物的需求，可单独设计明确的覆盖动作。

**验收**

| 场景 | 通过标准 |
|---|---|
| 以 `chapters/001.md`、`project.md`、`pending.md`、`pending-archive.md` 为目标，或把导出目录配置到 `chapters/` | 全部明确拒绝。比对原始文件字节与哈希，逐个一致。无新增成品。 |
| 绝对路径、越界路径、Windows 大小写别名、导出目录中的符号链接或目录联接 | 全部拒绝，项目外与权威目录中的样本不受影响。用实际 Windows 联接场景覆盖。 |
| TXT、HTML、EPUB 默认和合法自定义路径 | 文件可打开，格式、章数和回执路径一致。已存在文件完整保留。 |
| 两个导出同时竞争一个文件名，或出版文件写入／发布阶段故障 | 成功调用返回不同且完整的文件。失败调用没有半成品，已存在产物字节不变。 |
| 宿主审批拒绝一次、批准一次 | 拒绝后无输出，批准后在约定目录产生可读产物，回执可定位实际文件。 |

预期涉及 `packages/writer-export/src/index.ts`、`packages/writer-tools/src/index.ts`，回归放在 `packages/writer-export/tests/service.test.ts` 和工具测试中。Windows 与真人验收沿用发布清单。

## R2 · 让局部改稿范围由作者绑定

**拟定行为**

- 工作台把「改选中原文」与「整章改稿」作为两个明确入口。局部入口显示与 Markdown 正文对应的原文供作者选择，先预览目标章、原文和修改要求。源章完整哈希与唯一原文由服务端复读核验。富文本渲染无法映射到原文时，回到原文选择。重复选区要求作者扩大范围或重新选择。
- 推荐复用宿主现有命令通道登记局部请求。登记只校验和记录范围，由工作台交给宿主草稿等待作者发送。工具按会话和项目取回服务端记录的章节、原文和版本，使用现有局部补丁协议，防止模型修改文本参数后扩大选区。局部请求有效期间，本插件的章稿写入入口共用范围校验，模型漏传或修改请求标识、改用整章参数或通用章节更新，都拒绝该次写入。每个会话与作品组合只保留一个待执行的局部请求，成功保存后消费，原稿版本未变时失败可重试，作者可取消或重选。登记命令由人类入口调用。重载后旧请求失效并要求重选。
- 保留现有整章路径，要求明确声明整章范围，经宿主审批后执行。局部补丁有任一越界、锚点不唯一、重叠、模型返回全文或版本变化，整组拒绝。存储层仍按开始时的完整章稿哈希保存，覆盖生成过程中被外部编辑的情况。单靠改草稿提示的实现较省工，但范围仍由模型解释。服务端绑定可以验收模型省略或篡改参数时的实际行为。

**验收**

| 场景 | 通过标准 |
|---|---|
| 选中唯一正文后提交合法补丁 | 原选区内的预期改动准确落盘。完整文件比较证明选区前后正文逐字一致，文件元数据保持原义。 |
| 模型回传全文、混入一条区外补丁、锚点重复或重叠 | 整组拒绝，文件字节、哈希均不变，无保存或维护触发。 |
| 模型漏传局部标识、伪造选区／章号、使用整章或通用工具改章 | 有效局部请求期间全部拒绝触及章稿，工作台提示继续原请求、重选或明确取消。 |
| 选区创建后源章变化、模型生成期间源章变化、请求跨会话使用 | 拒绝过期或错绑的请求，保留最新稿，提示重新选区。同一会话对另一本书的请求无法使用。 |
| 工作台实际提交与明确的整章路径 | 浏览器夹具验证选择、预览、草稿交接和经工具落盘的区外对比。整章经作者明确发起及批准后仍可运行。正常续写与新建首章通过回归。 |

预期涉及 `packages/writer-ui/src/client/Panel.tsx`、`packages/writer-ui/src/client/actions.ts`、`packages/writer-tools/src/index.ts`、`packages/writer-core/src/index.ts`、`packages/writer-engine/src/index.ts`。测试从 `packages/writer-engine/tests/selection-rewrite.test.ts`、工具测试和 `packages/writer-ui/scripts/studio-browser-check.mjs` 扩展。此范围约束作用于写作插件的章稿入口，宿主原生编辑能力继续由其权限配置管理。

## R3 · 改稿后续接仍成立的待确认建议

- **修复**　取消用旧抽取抑制所有同义输出。新版章稿重新核对旧候选，仍成立的条目需要能在新版正文中核验的原句，再按新版源章哈希投递。只有在实际权威记录中可确定等价的已确认条目才压制。无法确定是否已落实的候选保留人工核对入口。沿用现有章稿哈希、部分／完整阶段去重和归档，旧确认请求继续按旧哈希失效。
- **验收**　真实 Markdown 项目同时放入仍成立、已删去和已确认三类候选，只改一处无关文字。新稿待办应仅提供仍成立、未确认的候选及新依据。过期节仍可追溯，重复运行同版本只投递一次。新版并发保存时，旧任务不能占用新版本投递。验收检查真实工作台“准备确认请求”的可用状态与来源哈希。
- **落点**　`packages/writer-engine/src/index.ts`、`packages/writer-engine/src/prompts.ts`，如需承载引句再更新维护领域类型和待办投影，重点覆盖 `packages/writer-engine/tests/maintenance-recovery.test.ts`。

## R4 · 准确区分维护成功、无发现和部分成功

- **修复**　首轮要求三个节都返回数组。重试只校验本次要求的节。显式空数组属于有效结果，缺节、非数组、坏条目及无效引用进入可见拒收。保留已通过的节及有效条目，重试不动未要求的节。重试耗尽时以部分完成落盘，报告缺的节和原因，下一次仍可重算。对旧派生缓存，升级后保留可读状态，复核时标为未使用新版校验；下次显式重算或正常维护重建，不在启动时批量调用模型。
- **验收**　覆盖三个合法空数组、缺节、类型错误、有效行混坏行、定向重试未回目标节、定向重试修复成功以及耗尽。逐项断言模型调用数、保留条目、落盘状态、用户可见原因和再次重算能力。校验缺项时禁止产生“已完整维护”回执。
- **落点**　`packages/writer-domain/src/maintenance.ts`、`packages/writer-engine/src/index.ts` 与存储校验；测试放在 `packages/writer-domain/tests/maintenance.test.ts`、`packages/writer-engine/tests/maintenance-recovery.test.ts`。先落此规则，再接入 R3 的新版候选核验。

## R5 · 统一目标章的伏笔可见性

- **修复**　在领域层共用按目标章构造的伏笔视图，写作上下文、带章号上限的 RAG 和单章审稿接入同一规则。故事事实取已实际发生的落点和里程碑。写作可收到本章计划的埋设／回收任务，审稿可见目标章已发生事实，检索保持已有章节上限语义。为历史视图使用实际章锚。对于含未来信息、缺乏分段锚的旧档案，提供能确认安全的标识、阶段和已锚定条目，隐藏整段未标时间的说明并披露覆盖不足。全书检索继续允许显式不设章号上限。
- **验收**　使用同一伏笔测试埋设前、埋设当章、埋设后回收前、回收当章及回收后，并补缺锚、倒序锚、已放弃、未来里程碑和计划早于实际埋设。捕获写作及审稿的真实模型输入，核对带章号上限的检索片段。未来正文词句不可出现，已实际发生的阶段或显式允许的本章计划可用。目标章以实际章文件定位，覆盖文件 ID 与手填展示章号冲突时仍不会泄露未来伏笔。
- **落点**　`packages/writer-domain/src/index.ts`、`packages/writer-domain/src/rag.ts`、`packages/writer-engine/src/review.ts`；扩展 `packages/writer-domain/tests/rag.test.ts`、`packages/writer-engine/tests/context-regressions.test.ts`。

## 确认后的实施顺序与验收

1. **R1、R2**。先分别复现导出覆盖和模型省略选区参数，再实现存储与工具边界。以原稿字节不变、预期操作仍可完成作为收口条件。
2. **R4、R3**。先校验抽取输出，再对新版章稿续接待办。以部分完成可恢复、有效候选可确认、同版无重复作为收口条件。
3. **R5**。先锁定按章可见性样例，分别验证写作、检索、审稿的真实消费路径。
4. **综合回归**。逐项复核、运行 `npm run typecheck` 与 `npm test`，再运行 `npm run smoke:windows`。干净 Electron profile 的真人批准和拒绝单独记录。若本机无头浏览器仍有环境故障，验收记录明确标为待完成。

## 实施复核

- R1 以独占临时文件和同目录硬链接完成发布。已存在的目标无法被替换，文件系统不支持安全发布时明确失败。真实 Windows 测试覆盖目录联接、原稿保护、并发和故障清理。
- R2 通过宿主的人类命令登记章节、范围和哈希。整章由宿主审批服务单次放行；拒绝后需要作者重发。浏览器夹具复用安装版前端、真实命令、真实写作服务和临时作品，测试模型注入越界与合法补丁。越界拒绝后文件字节一致，合法写入后正文仅选区变化、元数据语义保持。
- R4 对缺节、坏形状、无效引用和引句做检查；定向重试只核对目标节。旧缓存仍可读取，维护统计和工作台标为待重算，显式重算采用新版校验。
- R3 以真实项目回归新稿中仍成立、被移除和已确认的事实。新版使用逐字引句、完整章稿哈希和原有投递去重。只有证据明确等价的权威记录参与去重。
- R5 在写作请求、审稿请求和带章号上限的检索中使用章文件锚与伏笔投影。具备有效章锚的既往材料保留，档案无时间锚的自由正文从历史视图隐藏并由写作或审稿回执提示覆盖限制。
- 真实 Electron 干净 profile 的真人批准和拒绝仍待发布验收。自动验证使用宿主审批服务契约和受控回答，浏览器夹具独立验证真实命令到磁盘的写入范围。
