## 1. 用户行为

先识别已有小说项目，再区分尚未初始化和实际读取故障：

| 目录状态 | 面板行为 |
|---|---|
| 已有可识别的小说项目 | 正常打开，保留现有项目布局兼容性，不出现初始化按钮。 |
| 当前工作目录为空，或仅含 Git 元数据、空 `novel/` | 显示欢迎页、将创建的结构及「一键初始化」按钮。 |
| `novel/` 有可识别的中断标记，工作区其余条目符合初始化条件 | 显示「重试初始化」，仅补齐缺失项，保留现有文件。 |
| 目录非空，但没有可识别的小说项目 | 显示明确提示和冲突条目摘要，指导用户新建空工作目录，或打开已有小说项目的正确目录；禁止自动合并、覆盖或清理。 |
| 没有会话、没有写作服务、无权限、连接失败或目录读取失败 | 单独说明原因与恢复办法，不当作空目录。 |
| 面板项目位置与写作服务位置不一致 | 显示实际路径和修正指引；禁止在另一个项目中执行初始化。 |

初始化前在磁盘上核对全部条目。Git 元数据例外限于具有有效格式 HEAD 的 `.git/` 或 Git 工作树指针文件，其他隐藏条目照常参与非空判断。可采用已有的空 `novel/` 实体目录。

欢迎页取代无项目时的功能导航和通用错误，保留刷新入口。初始化执行中显示进度并禁止重复点击；成功后重新读取实际文件，进入可继续完善作品信息、创作准则和大纲的工作台。失败时保留具体原因与已完成情况，不伪报成功。

## 2. 初始化产物

默认在当前工作目录创建 `novel/`，沿用项目既有布局：

```text
novel/
    project.md
    principles.md
    outline.md
    events.md
    ideas.md
    pending.md
    pending-archive.md
    chapters/
    characters/
    plots/
    worldbuilding/
    style/
    exports/
    .writer/
    .gitignore
```

基础 Markdown 使用最少的中文填写指引；作品暂用“未命名作品”，不虚构题材、字数目标、人物或章节。`.gitignore` 排除可重建派生物与导出产物，不忽略正文、待办或归档。不初始化 Git，不调用模型。

## 3. 实现取舍

推荐使用宿主现成的人类命令通道，由初始化按钮直接调用确定性初始化逻辑。相较于把初始化要求追加到助手草稿，这能完成真正的一键操作，且无需模型额度；相较于另建文件写入 remote，可以复用现有会话身份、生命周期和命令结果。

初始化逻辑属于领域存储能力；UI 只发起操作并展示结果。服务端在写入前重新检查真实目录，避免页面加载后目录已发生变化仍继续写入。文件创建必须拒绝覆盖已有内容；重复请求、并发会话和中途失败需要有明确结果，失败处理只涉及本次创建内容。

路径一致性是验收前置条件：当前 UI 按会话工作区扫描，store 按配置的绝对 projectRoot 读写。实施须统一正常新会话的路径解析，保留显式项目配置并在不匹配时响亮提示；禁止通过修改一个共享的全局根目录来切换会话项目。不得出现按钮初始化成功但 writer_read/writer_update 仍读写旧项目的结果。

## 4. 实施计划与验证

1. 增加可区分的目录状态与确定性初始化能力 → 验证：空目录、隐藏文件、非空目录、已有项目、目录冒名文件、权限失败均分类准确；拒绝覆盖与并发创建可复现验证。
2. 接入宿主命令及项目路径校验 → 验证：不调用模型、不覆盖草稿，初始化与 writer_read/writer_update 指向同一项目；不同会话不串目录。
3. 增加欢迎页、非空目录指引、执行与失败状态 → 验证：浏览器实际构建产物中完成空目录到工作台的点击流程，非空目录无写入，窄屏可用。
4. 更新说明与迭代记录 → 验证：`npm run typecheck`、`npm test`、客户端浏览器检查；对抗审查后逐条复核、修复和重测，直至一轮无新问题。

## 5. 自审结论

- 仅调整空态文案无法完成一键初始化，必须补确定性写入能力。
- 仅在浏览器检查是否为空不足以保护已有文件，最终检查放在实际写入端。
- 面板与服务的根目录不一致是当前真实边界，不能把目录搭建成功当成写作工具可用。
- 不添加导入、自动修复旧项目或补齐非空目录功能；已有合法项目仍正常打开。
- 沿用当前工作区和未提交的 UI 改造，不自动提交、推送或修改参考子模块与宿主 profile。

## 6. 实施与审查记录

- `writer-core` 增加目录状态和初始化服务契约；`writer-store` 提供真实磁盘检查及基础结构创建，包含隐藏文件与标记类型校验、拒绝覆盖、跨会话初始化串行链、写入前与完成前复查、中断标记保留。初始化只允许空工作目录；被其他内容占用时不尝试导入或补齐。
- 复用宿主人类命令 `/writer-project-status`、`/writer-project-init`。命令使用已验证会话的 `header.cwd`，显式建立 `agents.withInitiator`；没有工作目录时明确失败。没有写作服务的会话收到使用指引；已有项目仍可在命令缺席时只读扫描。
- `projectRoot` 改为可选；bundle/preset 不再默认钉宿主启动目录。省略时在业务调用中使用发起会话的 `cwd/novel`，显式绝对路径维持固定项目兼容。store 索引、重建在飞任务及迁移状态按根隔离，engine 维护 pass、计数及排空同样按根隔离。RAG 内容哈希缓存与无状态导出无需新增项目缓存。
- 写作预设在安装版宿主按 revision 共享插件树，不能假设每会话独立服务。构造期不读取当前 Agent；固定项目装载时尝试旧归档迁移，会话项目首次访问时尝试，失败告警且不阻断正常稿件读取。
- UI 增加项目准备页，隐藏无效导航；初始化中防重复点击，成功后重扫进入工作台，失败保留原因。手动检查重新核对服务位置；文件监听正常刷新不重复执行状态命令。状态命令会留下宿主命令日志，这是复用命令通道的现有行为。
- 两路对抗审查并逐条复核，修复三项 P2：不存在的 novel/ 经父目录链接解析误报 mismatch、迁移故障阻断正常读取、检查失败仍沿用过期 empty。分别加入真实文件系统或浏览器失败回归，再修正通过；领域与 UI 收敛复审均无新问题。

## 7. 验证证据与边界

- 新增行为测试共 13 项，覆盖空/非空/隐藏/标记冒名、重复与并发、目录变化、中断、链接目录、坏旧归档、固定路径不匹配、真实宿主命令作用域与会话绑定、异项目同章号维护和客户端失败回执。测试均在实现前或修复前观察到预期失败。
- `studio-browser-check.mjs --init` 使用真实客户端构建产物、安装版宿主 React/基元/主题，以及真实 `CommandRuntime`、`AgentRegistry`、`SessionStore` 与临时磁盘目录。验证空目录到工作台、实际作品文件落盘、草稿不变、非空与隐藏文件保护、目录变化拒绝、跨会话、读取失败和陈旧 empty 清除；1280/960/720/390px 无整页溢出。
- 浏览器仍使用本地 HTTP 测试桥与无 Loop Agent 句柄；不能视作 Electron profile 的端到端验收。权限失败为受控故障注入，未调用真实模型或修改宿主 profile。旧 profile 中显式钉死的 projectRoot 仍优先，面板会提示路径不匹配；不能只更新代码就假定已移除部署覆盖。
- 运行日志及截图位于 `.tmp/project-init-*.log`、`.tmp/ui-implementation/browser/project-init-*.png`。最终全仓检查结果追加在 `docs/implementation-plan.md` §8 轮次 48。

## 8. 首轮前入口与增量刷新

- 安装版宿主 0.2.2-rc.1 的 `conversation.hero.options` 是会话级列表槽，位于新会话的工作区和预设一行。首轮前用槽提供的 `sessionId` 检查目录，工作区或同一会话的预设变化后重新检查。空目录提供“一键初始化”，非空或路径不匹配显示目录指引，成功后留在原会话并提示就绪。宿主仍根据自己的会话状态决定何时显示写作面板标签。
- 项目增量监听覆盖实际列举到的根目录、实体目录和一层卷目录。空目录可收到第一个文件的变更，移除目录或离开工作台时回收旧订阅。派生维护结果标记为部分完成时，面板继续提示待维护。

## 9. 快速起步与初始化恢复（2026-11-19）

- 首轮前入口和写作面板共用宿主创建命令。初始化成功后可将构思要求追加到现有草稿，由作者发送。工作台通过第一章大纲锚及正文判断是否已经有首章计划，内置的填写指引只用于引导。
- 跟随会话目录的项目在实体落盘前重新检查就绪状态。章节写作在调用模型前另做一次检查。显式固定根沿用既有写入兼容语义。
- 初次创建与重试按工作区真实路径串行。只有内容与插件标记一致的中断项目可重试，预期路径上的既有同类型目录与普通文件会保留。模板仍以独占方式写入。来源未明的标记和冲突类型继续提示检查。
- `studio-browser-check.mjs --blank-init` 运行安装版宿主的外壳、标题栏、会话视图链和空态槽，并接通真实的确定性命令及临时项目。 `--watch` 以深度为零的文件监听验证首文件出现、更新、删除和退订。
